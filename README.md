# 练记 · 微信小程序

基于《健身记录产品需求文档 v1.1（小程序优先）》实现的微信小程序版本。

## 如何运行

1. 打开微信开发者工具。
2. 选择“导入项目”或“打开项目”。
3. 项目目录选择本文件夹：
   `outputs/gymlog-miniprogram`
4. 使用你的正式小程序 AppID。云开发不支持测试号。
5. 编译后从“欢迎使用练记”页开始体验。

> 当前版本采用“本地优先 + 云端合并”：
> 没有网络时仍可继续记录；联网后自动同步到云端。

## 云开发配置（首次必须做）

### 1. 创建云环境

在微信开发者工具顶部点击「云开发」，创建一个云环境。

如果项目里有多个云环境，打开：

```text
utils/cloud.js
```

把 `CLOUD_ENV_ID` 改成你的云环境 ID：

```js
const CLOUD_ENV_ID = 'your-env-id'
```

如果只有一个默认环境，也可以保持为空。

### 2. 创建数据库集合

在云开发控制台的数据库中创建三个集合：

```text
gymlog_profiles
gymlog_workouts
gymlog_exercises
```

建议把集合权限设置为：

```text
所有用户不可读写
```

所有读写都通过云函数完成，避免客户端直接访问数据库。

### 3. 上传云函数

在开发者工具中右键以下目录，选择「上传并部署：云端安装依赖」：

```text
cloudfunctions/login
cloudfunctions/sync
cloudfunctions/clear
```

三个云函数分别负责：

- `login`：获取当前微信用户的 openid；
- `sync`：合并本机与云端训练数据；
- `clear`：清除当前用户的云端数据。

### 4. 验证

进入小程序「我的」页面，查看「云同步」卡片：

- 显示“云端已同步”表示登录和同步成功；
- 点击“立即同步”可以手动同步；
- 如果显示“同步失败”，检查云环境 ID、集合是否创建、云函数是否部署。

## 已实现功能

- 首次使用引导：单位、目标、经验、每周目标
- 首页：今日入口、继续训练、周目标进度、最近训练
- 训练记录：动作、重量、次数、组数、完成状态、备注
- 自动带出上次同动作表现，并把第一组默认填成上次数据
- 「上次」提示同时显示重量/次数/时长和完成组数
- 组间休息计时：+15s / -15s / 跳过、声音、振动、保持亮屏
- 有氧训练：跑步机跑步、跑步机爬坡、单车、划船机、跳绳、游泳
- 器械训练：补充坐姿卷腹器、坐姿转体机、船长椅举腿、辅助引体机、臀推机等常见固定器械动作
- 有氧支持持续/间歇两种模式，记录时长、距离、配速、心率和类型专属字段
- 跑步机跑步/爬坡根据体重、速度、坡度和时长自动估算热量
- 添加一组时自动复制上一组的数据
- 动作库：内置 168 个常见动作，支持搜索、肌群筛选、个人置顶
- 选择动作页固定搜索栏和部位筛选，只滚动动作列表
- 历史：月历、日期筛选、肌群筛选、训练详情
- 统计：本周训练次数、组数、训练量、4 周频率、PR、肌群分布、动作趋势
- 动作趋势：按天合并，折线展示最佳组估算 1RM，柱状展示训练容量
- 动作详情：最佳表现、估算 1RM、历史记录、可点击的折线/柱状趋势图
- 训练总结：时长、组数、训练量、本次 PR
- 编辑历史训练、复制训练、删除训练
- 设置：kg/lb、默认休息、每周目标、深色/浅色/跟随系统
- 数据导出：复制 JSON / CSV
- 微信登录、微信头像/昵称/身高/体重资料展示与云端同步
- 云同步、多设备数据合并
- 演示数据：设置页可一键生成示例训练

## 有氧记录

目前支持：

| 项目 | 专属字段 |
|---|---|
| 跑步机跑步 | 时长、距离、坡度、平均心率、热量 |
| 跑步机爬坡 | 时长、距离、平均坡度（无单位）、平均速度 km/h、平均心率、热量 |
| 单车 | 时长、距离、阻力/档位、踏频、平均功率、平均心率、热量 |
| 划船机 | 时长、距离、桨频、阻力档位、平均功率、平均心率、热量 |
| 跳绳 | 时长、次数、中断次数、回合/工作/休息、平均心率、热量 |
| 游泳 | 时长、距离、泳池长度、泳姿、平均心率、热量 |

有氧记录支持：

- 持续模式：录入总时长和距离；
- 间歇模式：录入回合数、工作时间和休息时间，自动计算总时长；
- 自动计算跑步配速、骑行速度、划船 500m 配速和游泳 100m 配速；
- 自动带出上次同项目的记录作为默认值。

## 个人信息与热量估算

「我的 → 编辑资料」可以填写：

- 微信头像；
- 昵称；
- 身高 cm；
- 体重 kg。

体重会用于跑步机和跑步机爬坡的热量估算。热量使用 ACSM 公式计算，并允许手动修改。估算结果会显示在有氧表单底部的绿色摘要条和「上次」记录中。

## 云同步机制

### 登录身份

小程序通过 `wx.login` 和云函数 `login` 获取当前微信用户的 `openid`。
不同微信用户的数据彼此隔离。

### 数据保存

本机数据仍然先写入：

```text
gymlog.db.v1
```

之后由 `utils/sync.js` 自动同步到云开发数据库。

### 时间格式

云数据库中的时间统一保存为带中国时区偏移的 ISO 8601 字符串，例如：

```text
2026-10-21T16:45:32.539+08:00
```

新产生的数据会自动使用 `+08:00`。历史数据需要部署并运行一次 `cloudfunctions/migrate-time`：

1. 右键 `cloudfunctions/migrate-time`；
2. 选择「上传并部署：云端安装依赖」；
3. 在云开发控制台运行一次该云函数，参数使用 `{}`；
4. 返回结果中的 `results` 会显示每个集合迁移了多少条记录。

### 后台查看用户数据

- `gymlog_profiles` 文档的 `_id` 使用 openid；
- 用户资料里保存 `profile.nickName`；
- 文档顶层额外保存 `displayName`，格式类似 `张三 · a1b2`；
- 每条 `gymlog_workouts` 文档额外保存 `nickName` 和 `displayName`，方便在云开发控制台直接识别用户；
- 用户修改昵称后，同步云函数会批量刷新该用户训练记录中的昵称字段。

### 多设备同步

- 打开小程序时自动拉取并合并云端数据；
- 本地修改后约 1.2 秒自动同步；
- 「我的 → 立即同步」可以手动同步；
- 每条训练、微信资料和设置都有 `updatedAt`；
- 同一记录以更新时间较新的版本为准；
- 删除操作使用 tombstone（墓碑记录），避免另一台设备把已删除数据重新同步回来；
- 墓碑记录保留 90 天。

当前采用“本地优先 + 最后修改时间合并”的策略，适合个人和少量朋友使用。如果以后做多人共享训练计划或教练端，需要进一步改成更细粒度的服务端同步模型。

## 数据说明

本地缓存 key：

```text
gymlog.db.v1
gymlog.cloud.meta.v1
```

云端集合：

```text
gymlog_profiles             用户设置、微信资料、displayName、当前训练、删除墓碑
gymlog_workouts             每次训练记录，冗余 nickName/displayName 方便后台查看
gymlog_exercises            历史自定义动作（兼容保留）
云存储 avatars/              微信头像文件
```

如果想重新开始：

- 在「我的 → 清空全部数据」中清空；
- 云端已连接时，会先清除云端数据，再清除本机数据；
- 也可以手动在云开发控制台删除集合中的记录。

## 当前限制

- 云同步采用整份本地数据与云端逐条合并，历史记录特别多时需要改成增量同步；
- 未实现训练模板、分享卡片、订阅消息；
- 休息计时以“应用在前台时可靠”为标准，锁屏/后台受微信和系统限制；
- 数据导出使用剪贴板 JSON/CSV，尚未做文件保存和分享；
- 动作示范图/视频、AI 建议、社交功能不在本版本范围。
